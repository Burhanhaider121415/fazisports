# Frontend implementation decision

The assigned GitHub repository was intentionally empty. The site is a brochure-style direct-wholesale experience with no backend, commerce, or dynamic data requirement. Use static semantic HTML, CSS, and browser-native JavaScript rather than installing an application framework or UI library. This gives Vercel a small static output, keeps product and legal pages directly addressable, and avoids dependencies unrelated to the brief.

The site needs no npm build command. Local preview uses Python's standard static HTTP server; JavaScript syntax can be checked with Node. The visual system is authored in `global.css` and later sections will extend it without a parallel component/theme system. The two approved families are self-hosted from official Google Fonts static WOFF2 assets with their OFL licenses included. The exact browser-rendered font state will be verified before WS-002 PASS.

This is a task-scoped implementation choice recorded after WS-001 confirmed there was no existing stack; it does not change the source-of-truth brief or authorize backend/e-commerce work.

The approved ten-product catalog is held in `assets/products/products.json` as the single source of SKU names, FZ references, exact descriptions, clean/model asset paths and alt text. `collection.js` renders the cards and, on selection, stores the exact selected record at `window.faziSelectedProduct` and emits `fazi:product-selected` with that record as event detail. `inspection.js` consumes that event in one native modal dialog, preserving the record's two images, exact product copy and product-specific WhatsApp draft. It creates no product route or second mapping. Model imagery is fetched only on hover-capable tablet/desktop widths; coarse-pointer mobile keeps the approved clean default and does not download the hover-only model set until a product is selected.

The Wholesale Capability section follows the Collection and provides the real `#wholesale` destination for the existing header navigation. It uses the approved three-block copy as black typography-led content with no images, extra CTA, or additional commercial claims. The section remains static and has no backend dependency.

The `#lookbook` section uses the byte-identical approved final MP4 with the existing approved 16:9 hero image as poster. It uses a native controlled `<video>` element with `preload="none"`; WS-009 adds muted in-view autoplay when motion is allowed, while preserving native pause/play controls and suppressing autoplay for reduced-motion and constrained connections. The inquiry-process section immediately follows on off-white and holds only the three exact explanatory steps; it does not create new form or conversion behavior.

WS-009 adds one shallow, normal-scroll Forward Cut transition from the hero to the collection, a reduced-motion-aware reveal for existing content, and responsive/fallback adjustments in `motion.js` and `global.css`. It does not pin or hijack scrolling, alter site copy/assets, or add an animation dependency.

The Final Contact and Footer complete the approved direct-wholesale journey using the existing black brand surface and static page structure. General WhatsApp and email links carry the approved prefilled drafts as standard URL schemes; `inspection.js` preserves the selected FZ reference and name in each product WhatsApp draft. The quiet shared Footer links to the homepage sections and the two directly addressable policy documents. Privacy and Terms content is held in static HTML; Terms Section 3 follows the corrected Step 8 wording. A user clarification accepts the email route as a normal clickable `mailto:` link, with no requirement to launch an external mail application or send a message. No form service, backend, persistent chat overlay or product-specific email action was introduced.
